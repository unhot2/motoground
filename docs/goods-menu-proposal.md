## 0. 조사로 확인한 전제

- `src/data/menu.js`의 `mainNav`에 이미 `{ label: '용품', to: '/#services' }` 가 자리표시로 존재 (전용 페이지 없음, 홈 서비스 섹션 앵커로만 연결).
- `services`(홈 서비스 그리드)에도 `{ label: '용품', icon: 'helmet', mobile: true }` 가 있음 (링크 없음, `helmet` 아이콘 이미 보유).
- **주의**: `src/data/place.js`의 `placeCategories`에 이미 `{ key: 'gear', label: '용품 · 딜러' }` 카테고리가 존재함. 이건 "용품을 파는 오프라인 매장(장소)"을 뜻하고, 이번에 만들 "용품" 메뉴는 "용품 그 자체를 사고파는 거래" 메뉴라서 의미가 다름. 사용자가 혼동하지 않도록 아래에서 네이밍을 구분한다.
- 기존 "중고매물"(Market)과 "플레이스"(Place) 모두 `pages/ + components/ + api/ + data/ + styles/*.css` 구조를 공유하고, `useAsync`, `Pagination`, `PhotoPicker`, `page-head`/`card`/`write-chip`/`my-select` 같은 공통 클래스·훅을 재사용함.

## 1. 메뉴 내용 제안

### 1-1. 컨셉
**"용품" = 바이크 관련 용품(헬멧/재킷/글러브/부츠/보호장비/통신기기/파츠/공구 등)을 회원 간에 사고파는 거래 마켓플레이스.**
"중고매물"이 바이크 완차 거래라면, "용품"은 그 외 모든 라이딩 장비 거래 — 구조적으로 **중고매물과 거의 동일한 패턴**을 재사용하는 것이 가장 일관되고 구현 비용도 낮음.

플레이스의 "용품 · 딜러" 카테고리(오프라인 매장 찾기)는 그대로 유지. 새 메뉴는 "물건 거래"이므로 영문 eyebrow 라벨을 `GEAR MARKET` 등으로 달아 "중고매물(USED BIKES)"과는 구분되지만 "오프라인 장소"와도 겹치지 않게 한다.

### 1-2. 카테고리 구성 (제안)
| key | 라벨 |
|---|---|
| helmet | 헬멧 |
| jacket | 재킷 · 수트 |
| glove | 글러브 |
| boots | 부츠 |
| protector | 보호장비(프로텍터) |
| comm | 통신기기 · 블랙박스 |
| mount | 거치대 · 캐리어 |
| tool | 공구 · 정비용품 |
| parts | 튜닝 · 교체파츠 |
| etc | 기타 |

### 1-3. 핵심 필드
- 공통(중고매물과 동일): 제목, 브랜드, 가격, 상태(새것/중고), 지역, 설명, 사진, 조회수, 찜수
- **용품만 추가 필요**: `size`(사이즈 — 헬멧/의류/부츠 등에서 중요, 중고매물에는 없는 필드), `category`(위 10종)
- 상태값 제안: `미개봉`, `새것(미착용)`, `중고-상`, `중고-중`, `중고-하` — 중고매물의 `status`/`accident` 체계보다는 단순화

### 1-4. 주요 기능 (중고매물 패턴 재사용)
1. 목록: 카테고리 필터(write-chip) + 상태 + 가격대 + 지역(select) + 검색(q) + 정렬, URL query string 저장
2. 상세: 이미지 갤러리, 기본정보, 판매자 정보, 연락하기, 찜하기, 유사 용품 추천
3. 등록/수정(로그인 필요): 사진 업로드(`PhotoPicker` 재사용), 카테고리 선택 → 상세정보 입력 — **중고매물처럼 모델 카탈로그가 없으므로 2단계 대신 1단계 단순 폼**을 제안 (브랜드명은 자유 입력)
4. 삭제, 상태 변경(판매중/예약중/판매완료)

### 1-5. 데이터 구조 (제안 — Supabase)
`listings`/`places` 패턴과 동일하게:
- `goods` (title, category, brand, size, price, condition, region, description, view_count, like_count, status, seller_id, created_at, updated_at)
- `goods_images` (goods_id, path, sort_order)
- `goods_contacts` (goods_id, 1:1, 비공개 연락처)
- `goods_likes` (goods_id, user_id 복합 PK)
- 트리거: `touch_updated_at`, `sync_goods_like_count`, `protect_goods_counters` — 기존 Market/Place 트리거 함수와 동일 패턴 재사용
- RLS: 읽기는 누구나, 쓰기는 본인 또는 `is_admin()`만 — 기존 정책 그대로 적용

### 1-6. 메뉴 노출
- `mainNav`: `{ label: '용품', to: '/#services' }` → `{ label: '용품', to: '/goods', match: '/goods' }` 로 교체
- `services`: `{ label: '용품', icon: 'helmet', mobile: true }` → `to: '/goods'` 추가
- `mobileTabs`(하단 5슬롯: 홈/커뮤니티/매물/채팅/차고)에는 **추가하지 않음** — 플레이스도 하단탭에 없는 것과 동일한 기존 패턴 유지, 슬롯 과밀 방지
- 라우팅(`App.jsx`): `/goods`, `/goods/:id`, `/goods/new`(인증), `/goods/:id/edit`(인증) — Market 라우트 패턴과 동일

## 2. 디자인 초안 (와이어프레임 레벨)

기존 디자인 토큰(`global.css`: 블랙+골드 테마, `--font-display`/`--font-en`, `.page-head`/`.card`/`.write-chip`/`.my-select`/`.btn--gold`)을 그대로 사용. 신규 CSS는 `src/styles/goods.css` 한 파일로 제한.

│ 상태: (전체)(새것)(중고)   지역: [select ▾]     │

### 2-4. 홈 화면 변경
- `ServiceGrid`의 "용품" 아이콘 클릭 시 `/goods`로 이동 (기존 플레이스홀더 제거)
- 필요 시 `features`에 "용품" 카드 추가 고려(선택 사항, 승인 시 결정)

## 3. 승인 시 선택할 옵션

| 항목 | 옵션 A (권장) | 옵션 B |
|---|---|---|
| 구현 범위 | 목록/상세/등록/수정/삭제 풀구현 (Market과 동급) | 1차: 목록+상세만, 등록 기능은 추후 |
